# 做T账本

一只股票一个卡片，记录每一笔做T的买入与卖出，自动算盈利、持有时间和年利率。

## 功能

### 首页
- 一张卡片 = 一只股票，名称和代码在创建时自己填
- 卡片内容：
  - 上行：股票名 / 代码，右上角「未出T n」「已T m」两个标签
  - 虚线下方（全部 / 当前口径）：**盈利**（全部已T记录盈利合计）、**占用资金**（当前未出T记录的买入金额 + 买入手续费）、**胜率**（全部已T口径）
  - 实线下方（近一年口径）：**近一年盈利**、**近一年巅峰占用**（最近一年里同时压在场上的钱最多到过多少）、**年利率**（前两者相除）
  - 实线那三格排成一条是有意的：分子 ÷ 分母 = 结果，一眼能对上，不用来回找
- **长按卡片**弹出菜单：修改股票信息 / 调整在首页的顺序 / 删除
- 「调整在首页的顺序」进入排序模式：按住卡片上下拖动，右侧提示改成「完成」，拖好点完成后顺序落库
- 新建的股票排在最前面
- 右上角两个图标：📊 统计 →、⇄ 数据导入导出

### 股票详情页
点首页卡片进去，可以创建 / 修改 / 删除买卖记录。记录列表**分两档**：

| 档位 | 内容 | 排序 |
| --- | --- | --- |
| b（在上面） | 未完成做T（未出T） | 买入价从低到高 |
| a（在下面） | 已完成做T（已T） | 卖出时间从近到远 |

顶部有该股票的汇总（盈利、占用资金、近一年巅峰占用、年利率、胜率），右上角可进该股统计、编辑股票、删除股票。

#### 港币显示开关（仅港股通）

港股通股票的顶栏多一个 `¥ | HK$` 分段开关，**A股股票不显示**。高亮的那一段就是当前显示币种，
点另一段切过去；页面上**凡是带 HK$ 的都是港币**，人民币口径下价格不带符号、金额带 ¥，和以前一样。

| 项目 | 港币口径怎么来 |
| --- | --- |
| 价格 / 成交额 | 人民币 ÷ 该侧成交日的结算汇兑比率；当初按港币填过的记录直接还原原币值，不重除 |
| 手续费 | 折算出来的对照值。港股通手续费本来就是**按人民币扣**的，别拿这个数去对交割单 |
| 盈利 | **按港币重算**：卖出港币额 − 买入港币额 − 双边港币手续费，不含买卖两天之间的汇率损益 |
| 顶部汇总卡 | 盈利 / 占用资金 / 近一年巅峰占用跟着变港币；胜率、年利率是比值，用港币口径的盈利重算 |

- 汇率取用和录入页同一套规则：买入日按「卖出结算汇兑比率」、卖出日按「买入结算汇兑比率」，
  逐日查 `FxRateRepository`（内置 2014-11-17 起的全量历史 + 用户覆盖表），全程离线
- 开关**只影响这一页的显示**：库里、首页卡片、统计页一律还是人民币。也不跨页面记状态，
  每次进详情页默认回到人民币 —— 免得切了港币忘了切回来，把港币数当成到账的钱看
- 所以港币口径的「盈利 / 胜率 / 单笔年化」可能和人民币口径不一致，差额就是那段汇率损益
  （人民币赚、港币亏的边界情况真存在）。要和券商对账请以人民币口径为准
- 每张卡片底部写明这个港币数按哪个汇率折的：「按结算汇率折成港币　买 0.85005 · 卖 0.84995（1 港币 = ? 元）」；
  当初按港币填过的记录则写「原按港币填」，说明港币数是直接还原原币值、不是再除一次

### 买卖记录卡片

```
┌──────────────────────────────────────────────┐
│ [未出T]                              ✎   🗑   │
│   买入                │        卖出           │
│   价格   380.000      │   价格   392.000      │
│   金额   ¥38,000.00   │   金额   ¥39,200.00   │
│   手续费 ¥5.00        │   手续费 ¥5.00        │
│   时间   2026-09-01   │   时间   2026-09-03   │
│ - - - - - - - - - - - - - - - - - - - - - -  │
│   盈利           持有时间         单笔年化    │
│   +¥1,190.00     2天               5712.5%   │
└──────────────────────────────────────────────┘
```

「单笔年化」是这一笔自己的资金效率：`(盈利 ÷ 买入金额) ÷ (持有天数 ÷ 365)`，和首页那个股票级的
**年利率**（近一年盈利 ÷ 近一年巅峰占用资金）不是一个东西，所以刻意用了不同的名字。

### 添加 / 编辑记录
- 买入价、买入金额、买入手续费、买入日期
- 一个「已卖出」开关控制卖出侧：关掉就是未出T
- 打开后出现卖出价、卖出金额、卖出手续费、卖出日期
- 买卖时间都**只选到天，不记时刻**，选完日期直接确定
- 底部**实时预览这条记录长什么样**，用的就是列表卡片本身
- 校验：买入价/买入金额必填；卖出侧要么整组填、要么整组不填；卖出日期不能早于买入日期

### 统计页
- 首页右上角进 → 统计全部股票；详情页右上角进 → 只统计那一只
- **顶部可以选统计区间**：
  - 快捷档：近一年（默认）/ 近半年 / 近三月 / 全部
  - 「按年/月」：选某个自然年（2026 全年），或者某年某月（2026 年 8 月）
  - 灰色月份表示该月没有记录；选完点「关闭」，数据实时跟着变
- 汇总卡片：盈利、巅峰占用资金、收益率、占用资金、胜率；下面是各股票明细（按区间盈利排序）
- 收益率那一格的标题会跟着区间变：近一年 → 「年利率」，近半年 → 「近半年收益率」，按月 → 「月度收益率」。
  一年以内的收益率没有年化，所以不叫年利率，免得误导。

### 数据导入导出
- 导出：全部数据写成一个 JSONL 文件（每行一条记录），保存位置自选，不需要存储权限
- 导入两种方式：
  - **覆盖导入**：先清空现有数据再按文件还原，保留原始编号，适合恢复备份
  - **追加导入**：保留现有数据，把文件内容并进来，新记录重新分配编号并对齐外键
- 整个导入在一个数据库事务里完成，中途出错整体回滚
- 单行损坏、类型未知的记录会跳过并提示

#### JSONL 备份格式
整个文件一行一条 JSON，行尾不加逗号，用 `_type` 区分记录属于哪张表：

```jsonl
{"_type":"meta","app":"tj-ledger","format":"tj-ledger/jsonl","schema":1,"exported_at":"2026-09-22 15:20:00","counts":{"stocks":1,"trades":2}}
{"_type":"stock","id":1,"name":"腾讯控股","code":"00700","sort_order":1,"created_at":"2026-09-22 15:10:00"}
{"_type":"trade","id":1,"stock_id":1,"buy_price":380.0,"buy_amount":38000.0,"buy_fee":5.0,"buy_time":"2026-09-01","sell_price":392.0,"sell_amount":39200.0,"sell_fee":5.0,"sell_time":"2026-09-03","created_at":"2026-09-22 15:12:00"}
```

买入 / 卖出时间存的都是 `yyyy-MM-dd`（只到天）。
1.0 版本导出的备份里带时刻（`yyyy-MM-dd HH:mm`），导入时照常识别，不用手工改。

导出和导入都按字段动态处理（导出读表里真实存在的列，导入按文件里的字段落库），
所以以后给表加字段这里不用改，老版本读到不认识的字段会忽略、认识的也不会丢。

## 计算公式

```
一笔的成本     = 买入金额 + 买入手续费
盈利           = 卖出金额 − 买入金额 − 买入手续费 − 卖出手续费
持有时间       = 已T：卖出日期 − 买入日期；未出T：买入日期 至 今天
                 两端各截到当天 0 点后数整天数，和填几点几分无关
                 已T 不足 1 天按 1 天计（当天买当天卖就是这种情况）
单笔年化       = (盈利 ÷ 买入成本) ÷ (持有天数 ÷ 365) × 100%
                 ↑ 只出现在记录卡片里，衡量单笔资金效率
                 分母用买入成本而不是买入金额：分子已经扣了双边手续费，
                 分母也要把买入手续费算进去，口径才和组合级的收益率一致
```

组合口径（首页卡片 / 统计页）：

```
巅峰占用资金   = 区间内逐日统计「当天还没卖出的买入成本之和」，取最大值
                 占用区间 = 买入日 ~ 卖出日（含两端）
                 未卖出的算到今天；买入早于区间起点的跨期持仓照样计入
                 区间尾端超过今天的部分不算（当年的 12 月里，未来那几个月不模拟）
收益率         = 区间内已T盈利 ÷ 区间巅峰占用资金 × 100%
年利率         = 窗口为最近一年时的收益率
股票的盈利     = 该股已T记录盈利之和
股票的占用资金 = 该股未出T记录的（买入金额 + 买入手续费）之和（当下状态，不随区间变）
股票的胜率     = 该股已T中盈利笔数 ÷ 已T笔数
```

几个刻意的选择：

- **占用区间含卖出日**。做T大量是「当天买当天卖」，如果卖出当天就不算占用，日内T的占用会变成 0，
  年利率的分母就没了。含两端后日内T至少占 1 天。
- **巅峰占用逐日模拟，而不是把各笔金额相加**。相加会把时间上根本不重叠的持仓累到一起，数值严重虚高。
- **统计页的「全部」按组合算**：同一天各股的占用先相加再取最大值，而不是「各股峰值再相加」。
  后者会把不同股票错峰的持仓加在一起，高估占用、低估收益率。
- 巅峰占用为 0 时收益率显示「—」，不做除零。

## 技术栈

## 数据库设计

### stocks 表
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 主键 |
| name | TEXT | 股票名称 |
| code | TEXT | 股票代码（不可重复，可留空） |
| sort_order | INTEGER | 首页上下顺序，越小越靠上 |
| created_at | TEXT | 创建时间 |

### trades 表
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 主键 |
| stock_id | INTEGER | 关联股票，级联删除 |
| buy_price | REAL | 买入价 |
| buy_amount | REAL | 买入金额 |
| buy_fee | REAL | 买入手续费 |
| buy_time | TEXT | 买入日期（yyyy-MM-dd） |
| sell_price | REAL | 卖出价，NULL = 未出T |
| sell_amount | REAL | 卖出金额 |
| sell_fee | REAL | 卖出手续费 |
| sell_time | TEXT | 卖出日期（yyyy-MM-dd），NULL = 未出T |
| created_at | TEXT | 创建时间 |

数据库版本 `1`。升级不看版本号分支，而是按「表 / 列是否真实存在」逐项补齐，从任意老版本升上来都不会丢数据；
装回旧版 APK 也不会崩（`onDowngrade` 走同一套补齐逻辑）。
卖出侧四个字段整组同生同灭：没卖出就全写 NULL，不留半截脏数据。

买卖日期列一直是 `TEXT`，1.0 的 `yyyy-MM-dd HH:mm` 和 1.1 的 `yyyy-MM-dd` 都能读，
所以从 1.0 升到 1.1 不需要做数据迁移，旧记录里的时刻会被忽略（按整天算）。

## 构建

```bash
export ANDROID_HOME="D:/Android"

./gradlew.bat assembleDebug    # 产物 app/build/outputs/apk/debug/app-debug.apk
```
